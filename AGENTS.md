# Project rules
- Keep player applications separate from supporting membership; use server-validated approval, private versioned agreements, scoped expiring invitations and atomic invitation creation with provider idempotency so applying never grants access or triggers duplicate welcome emails.
- Player payment and eligibility verification must retain source/actor/time separately from self-confirmation; unsupported Spond/DNB automation stays a manual task, and agreement delivery never depends on payment completion.
- Keep homepage video layout opt-in in LatestVideos (2x2 on large screens, three across below xl, three stacked on mobile). Reuse the "Rundt laget" cards with the official Instagram API via the instagram-feed function; server-only cache/credentials, atomic refresh lease and bounded failure backoff prevent per-visitor Meta calls and idle activity. Keep Instagram read authorization separate from Facebook publishing credentials; never scrape or use a profile iframe.
- Keep full standings mobile sizing scoped to `.full-standings` with fixed percentage columns and stepped font sizes so all statistics fit without changing other tables or desktop layouts.
- Keep Matches Scraper source failures explicitly typed and test its exported runner with injected dependencies; this preserves fatal backend/config errors without live-service test side effects.
- Every new public table or view must be created in one migration with explicit least-privilege GRANTs per role (anon only for intended public reads/inserts, authenticated per RLS policy, service_role ALL), ENABLE ROW LEVEL SECURITY, its RLS policies, and sequence USAGE grants when it uses serial/identity; never use ALTER DEFAULT PRIVILEGES. Why: from 2026-10-30 Supabase no longer auto-grants new public tables, so fresh rebuilds would otherwise lock the Data API.

- Sports standings must be replaced through the service-role-only configured, validated atomic season RPC; both official division calendars must validate before any write, and goal-club triggers must branch by table before accessing match-only columns. Why: source/DB failures must preserve the prior complete standings and never break standings-trigger execution.
- Resolve imported and admin-edited match wall times through the shared Europe/Oslo resolver, rejecting nonexistent DST times and choosing the first repeated autumn occurrence. Why: stored timestamps must not depend on fixed offsets or browser timezone.

- Store active sports configuration in sports_seasons; public/sports-season.json is the versioned GitHub change-gating mirror and backend sync rejects mismatches. Why: idle checks must not contact the backend and season rollover must not silently use stale IDs.
- Save season drafts through the existing settings screen; activation publishes and verifies the GitHub manifest before a server-only atomic activation RPC, without dispatching workflows. Why: a board member can roll over seasons without code changes while mismatches fail safely.
- Scope every goal-club entry/read/invoice/winner to its enrollment season; database validation prevents cross-season invoices. Why: previous seasons never automatically renew.
- Lazy-load routes except the homepage with a stable Suspense fallback. Why: public visitors must not download heavy admin route code upfront.
- Newsletter editorial status and delivery state are separate; atomic delivery claims and monthly automatic uniqueness prevent duplicate campaigns, and post-claim failures require explicit recovery. Why: uncertain provider outcomes must never silently replay a real recipient list.
- Complete both migration histories before running the idempotent sports configuration bootstrap on an empty backend. Why: active configuration is application data rather than an implicit runtime default.
- Newsletter preference links use purpose-scoped expiring HMAC tokens, never an email/ID pair; persist delivery intent before calling the provider and block ambiguous campaign replay. Why: links must not authorize by guessable identity, and provider success must leave a reconciliation trail.
- Claim each goal-club invoice atomically before provider delivery; never automatically reclaim sending/uncertain invoices, and derive closure completion from persisted invoice states. Why: provider idempotency alone cannot protect overlapping or delayed retries.
- Keep the schema-replay harness disposable with explicitly inert managed-service and crypto stubs; never reuse it for production or security validation. Why: full application migration ordering can be tested without contacting services, but platform behavior must be verified separately.
- Require boolean newsletter preference updates and keep completed preference/delivery writes successful when optional audit logging fails; never expose provider bodies or raw exceptions. Why: malformed requests must not resubscribe members, and an audit failure must not encourage duplicate delivery or leak credentials.
- Discover the next league season in GitHub only (scripts/fingerprint/discover.py, daily after New Year) from the stable fotball.no team pages; activate via the secret-authenticated `discover` action only when both teams have exactly one validated league tournament, and never override a manual draft. Why: rollover needs no code change or Lovable runs, while manual tournament IDs stay the fallback.
